## IoC(제어의 역전)이란

웹 작업을 하다 보면 프레임워크와 라이브러리의 차이에 대한 의문을 가지게 된다. 여기서 프레임워크와 라이브러리의 차이는 크게 IoC라고 설명을 듣게 되는데, IoC는 무엇일까?

IoC는 제어의 역전(Inversion of Control)이라는 뜻인데, 1988년 Ralph E. Johnson과 Brian Foote가 "Designing Reusable Classes"라는 논문에서 처음 이름을 붙였다. 실제로 널리 쓰이게 된 건 그보다 나중인 2000년대 초, 자바 진영에서 Spring 같은 DI 프레임워크가 유행하면서부터다.

제어의 역전이란 결국 누가 호출을 하는지에 대한 문제다. 내가 주체가 되어 호출을 하면 직접 호출 방식이고, 남이 주체가 되어 나를 호출한다면 IoC를 사용한다고 볼 수 있다.

IoC는 개념적인 단어로 기준을 어떤 관점으로 잡느냐에 따라 달라진다.

### 좁은 관점에서의 소스코드 예시

**IoC가 아닌 경우**(직접 호출)
```js
function sayHi() {
  console.log('hi');
}
sayHi();
```

**IoC인 경우**(forEach의 호출)
```js
function log(n) {
  console.log(n);
}
[1, 2, 3].forEach(log);
```
`log`를 내가 직접 부르는 게 아니라, 언제 `log`를 부를지는 `forEach`가 정한다.

**IoC인 경우**(브라우저의 호출)
```js
function sayHi() {
  console.log('hi');
}
button.addEventListener('click', sayHi);
```

### 브라우저는 호출을 어떻게 할까?

내가 만든 버튼을 클릭할 시 브라우저는 화면에서 객체를 찾은 후 콜백함수를 실행하도록 명령을 한다. 예를 들면 홈페이지가 다 로딩된 후 화면을 띄워달라던지, 10초 뒤 팝업이 꺼지게 해달라던지 등등이 해당된다.

*브라우저에서 실행되는 코드는 C++로 크로미움 안에 복잡하게 얽혀 작성되어 있다는데, 이건 넘어가자.*

이렇게 호출자의 영역 바깥에서 호출할 수 있도록 스위치를 손에 쥐어주는 것이 IoC(제어의 역전)라고 보면 된다.
