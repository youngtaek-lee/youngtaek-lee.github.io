## 왜 정리했나

그동안은 vanilla CSS로 브랜드마다 다른 톤앤매너를 직접 짜는 작업을 주로 해왔다. 그런데 실무에서는 빠른 속도로 여러 페이지를 찍어내야 하는 경우가 많고, 이럴 때 Tailwind CSS나 Bootstrap 같은 프레임워크를 쓰는 곳이 많다는 걸 알게 됐다. 개념부터 다시 정리한다.

## Tailwind CSS — utility-first

클래스 하나가 CSS 속성 하나(또는 소수)에 대응한다.

```html
<button class="px-4 py-2 rounded-lg bg-orange-500 text-white">Click</button>
```

- 마크업 안에서 스타일이 바로 보여서 새 CSS 파일을 오가지 않아도 됨
- 빌드 시 실제 사용한 클래스만 추출(purge)해서 최종 CSS 용량이 작음
- 커스텀 디자인 구현이 자유로움 — 프로젝트마다 다른 느낌을 내기 쉬움
- 단점: 클래스가 길어져서 마크업이 지저분해 보일 수 있음, 초반엔 클래스 이름 외우는 러닝커브 있음

## Bootstrap — 컴포넌트 기반

미리 만들어진 컴포넌트 클래스를 그대로 가져다 쓴다.

```html
<button class="btn btn-primary">Click</button>
<div class="card">...</div>
```

- 카드, 모달, 네비바, 그리드 시스템까지 완성된 컴포넌트를 바로 사용
- 러닝커브가 낮고, 빠르게 "일단 동작하는 화면"을 만들기 좋음
- 단점: 커스터마이징하려면 기본 스타일을 override해야 해서 오히려 손이 더 갈 수 있음, 결과물이 서로 비슷해 보이기 쉬움

## 언제 뭘 쓸까

- 브랜드 아이덴티티가 중요한 랜딩페이지, 디자인 시안을 정교하게 맞춰야 하는 작업 → **Tailwind**
- 관리자 페이지, 내부 툴처럼 디자인보다 속도가 우선인 작업 → **Bootstrap**
